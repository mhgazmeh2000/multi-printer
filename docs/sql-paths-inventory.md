# فهرست مسیرهای SQL خام — نقشه‌ی ترجمه برای PostgreSQL (فاز E)

**فاز:** E.0، کار E.0.12. **وضعیت:** فقط مستندسازی؛ در این گام هیچ SQLای تغییر نکرده است.
**روش:** پیمایش AST روی `core/`, `web/`, `tools/`, `create_admin.py`, `models.py`, `config/`
(بدون `tests/`)، همه‌ی فراخوانی‌های `execute`/`executemany`/`executescript` + grep روی
سازه‌های مخصوص SQLite. تاریخ: ۲۰۲۶-۱۰-۰۳.
**مرجع مکمل:** `docs/db-adapter.md` §۵ («چیزهایی که adapter انجام نمی‌دهد») — این سند همان
فهرست را با شماره‌خط دقیق و نقشه‌ی تبدیل کامل می‌کند.

### تفصیل چند مورد (دام‌های پنهان)

**۱) `INSERT OR REPLACE`:** ترجمه‌ی بی‌دقت به `ON CONFLICT DO UPDATE` **بدون فهرست ستون‌ها**
همان باگ «NULL شدن ستون‌های غایب» را می‌سازد که در E.0.4 اثبات شد
(`docs/insert-or-replace-inventory.md`) ⇒ هر محل باید فهرست کامل ستون‌ها را صریح بنویسد.
`web/routes/import_db.py:187` ویژه است: `verb` پویا ساخته می‌شود و در
`ALLOWED_IMPORT_TABLES` تنها سه جدول «replaceable»اند.

> یادداشت شمارشی: `docs/db-adapter.md` §۵ عدد «۸ نقطه» را برای `json_extract` آورده بود؛
> شمارش دقیق این سند **۱۰** است (۹ در `core/database.py`، ۱ در `web/routes/metrics.py`).

**۲) `json_extract`:** در PG اگر `details` همچنان `TEXT` بماند، باید
`(details::jsonb)->>'event_id'` نوشت؛ اگر `JSONB` شود، `details->>'event_id'` کافی است.
تفاوت مهم: `json_extract` در SQLite رشته‌های عددی را برمی‌گرداند و در `:754-755` با
`CAST(... AS INTEGER)` مقایسه می‌شود ⇒ در PG همان cast لازم است وگرنه مقایسه‌ی
متن/عدد بی‌صدا غلط می‌شود.

**۳) `substr` — بسته شد (E.3.4):** سه نقطه‌ی `web/routes/stats.py` بازنویسی شدند و
سبد روزانه به پایتون منتقل شد (`to_local_day`)، پس دیگر نه خطای نوع در PG داریم و نه
خطر «بی‌صدا UTC شدن مرز روز». برای E.4 فقط بازبینی هم‌خوانی با `TIMESTAMPTZ` لازم است.

**۴) PRAGMA:** دو محل (`core/database.py:228`, `:234`) هندلر خطای «locked» دارند که در PG
بی‌معنی می‌شود و باید به SQLSTATE نگاشت شود (`docs/sqlite-excepts-inventory.md`).

**۵) AUTOINCREMENT:** مهاجرت داده id را درج نمی‌کند
(`web/routes/import_db.py:175` ستون `id` را حذف می‌کند) — ولی در سناریوی بازگردانی از PG
(`tools/export_from_pg.py`) id صریح درج می‌شود ⇒ در SQLite بی‌مسئله، اما اگر روی PG هم
id صریح درج شود، `setval` لازم است.

**۶) `lastrowid`:** جست‌وجوی انجام‌شده در E.0.10 نشان داد تنها یک مصرف واقعی وجود دارد
(`core/database.py:510` — ساخت کاربر)؛ adapter فقط فوروارد می‌کند. تغییر = دو خط.

**۷) `executemany`:** تفاوت رفتاری مهم: SQLite پس از خطا در یک سطر، بقیه را ادامه می‌دهد
(در حلقه‌های try/except)؛ PG کل تراکنش را abort می‌کند. برای
`core/database.py:1150` (درج دسته‌ای سنسور در یک `with db_connection(commit=True)`)
باید مرز تراکنش صریح شود.

**۱۳) مقایسه‌ی متنی/زمانی:** امروز `timestamp >= ?` با رشته‌ی ISO مقایسه می‌شود
(`web/routes/stats.py:28/36/80` با `start_date` محلی). پس از `TIMESTAMPTZ`، پارامترِ
naive با TimeZone نشست تفسیر می‌شود ⇒ جابه‌جایی ۳:۳۰. همان الزام آگاه-UTC
(`docs/timestamp-consumers.md` §۶).

## ۴. ترتیب پیشنهادی ترجمه در فاز E

۱. **ابتدا** زیرساخت: `placeholders.py` (escape `%`)، `AUTOINCREMENT`→`IDENTITY`،
   `lastrowid`→`RETURNING` (چون فقط یک محل است)؛
۲. **schema:** `TEXT` timestamp→`TIMESTAMPTZ` + `TimeZone=UTC` + boolean→`BOOLEAN`؛
۳. **مسیرهای نوشتن بحرانی:** ۶ محل `INSERT OR REPLACE` (با فهرست کامل ستون‌ها)؛
۴. **مسیرهای خواندن:** `json_extract` (۱۰ نقطه: ۹ در `core/database.py` + ۱ در `web/routes/metrics.py`)،
   `substr` (۳ نقطه)، `COLLATE NOCASE`؛
۵. **خطاها/تراکنش:** PRAGMAها و هندلرهای «locked»، `executemany` دسته‌ای؛
۶. **جدول `meta` و ابزارها:** `sqlite_master`/`PRAGMA table_info` در `import_db.py`
   (ابتدا تصمیم محصولی: بازنشستگی یا ترجمه)؛
۷. **ابزارهای `tools/`:** فاز F.

در هر گام: `docs/cutover-plan.md` گام ۲ (۲۷۳ تست روی هر دو backend + golden ۱۰/۱۰) باید سبز بماند.

## ۵. بازتولید اندازه‌گیری‌ها

```bash
# پیمایش فراخوانی‌های SQL (AST)
python - <<'PY'
import ast, io
from pathlib import Path
n = 0
for f in [p for d in ("core","web","tools") for p in Path(d).rglob("*.py") if "__pycache__" not in str(p)] + \
         [Path("create_admin.py"), Path("models.py")]:
    tree = ast.parse(io.open(f, encoding="utf-8").read())
    n += sum(1 for x in ast.walk(tree) if isinstance(x, ast.Call)
             and isinstance(x.func, ast.Attribute) and x.func.attr in ("execute","executemany","executescript"))
print("مجموع محل‌های SQL:", n)
PY

grep -rn "INSERT OR REPLACE" --include=*.py core web tests      # ۶ محل
grep -rn "json_extract" --include=*.py core web                 # ۱۰ نقطه (۹ + ۱)
grep -rn "substr(timestamp" --include=*.py web                  # ۳ نقطه
grep -rn "AUTOINCREMENT" --include=*.py core                    # ۷ مورد
grep -rn "lastrowid" --include=*.py . | grep -v tests/          # database.py:510 + adapter
grep -rn "PRAGMA" --include=*.py core web                       # ۴ محل فعال + import_db
```
