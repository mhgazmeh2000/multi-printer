# تکرار محدود آزمون کپی پس از ANALYZE

این ابزار فقط برای کپی از پیش تأییدشدهٔ ویندوز است؛ مجوز فعال‌سازی تولید نیست.

## شواهد دریافت‌شده

- کپی PostgreSQL 17.5، شناسهٔ `7709766716166001212`، پورت loopback `55439`.
- بازیابی تأییدشده با 2,256,043 ردیف تاریخچه و 51 جایگاه پرینتر/رنگ.
- اولین خواندن مسیر قدیمی با سقف 120 ثانیه متوقف شد؛ فعال‌سازی شروع نشد.
- خلاصهٔ لاگ یک statement timeout را نشان داد؛ شمارندهٔ FATAL نیز یک بود و علت آن از خلاصه معلوم نیست.
- کلاستر پس از شکست خاموش شده است. آزمون برابری و سرعت مسیر جدید هنوز نتیجه ندارد.

## تغییر ابزار

گزینهٔ صریح `--retry-baseline-after-analyze` فقط گزارش شکست شناخته‌شدهٔ اولین خواندن، بدون commit فعال‌سازی و با خاموشی تأییدشده را می‌پذیرد. گزارش، سورس و لاگ‌های جدید پسوند `-analyzed` دارند؛ شواهد قبلی حذف یا بازنویسی نمی‌شوند. وجود شواهد تلاش جدید مانع تکرار خودکار است.

پس از کنترل زندهٔ آدرس، پورت، کاربر، دیتابیس، مسیر data و system identifier، ابزار خاموش‌بودن derived state را کنترل و فقط `ANALYZE public.toner_snapshots_v2` را اجرا می‌کند. این عملیات آمار برنامه‌ریز را تغییر می‌دهد، نه رکوردهای تاریخچه را. lock timeout یک ثانیه و statement timeout همان 120 ثانیه است. زمان ANALYZE و reltuples قبل/بعد گزارش می‌شوند؛ reltuples به‌تنهایی شاهد کامل بودن آمار ستون‌ها نیست.

بکاپ منطقی معمول PostgreSQL 17 آمار برنامه‌ریز را منتقل نمی‌کند. نبود ANALYZE صریح پس از restore نقص آماده‌سازی آزمون قبلی بود، اما ثابت نمی‌کند تمام کندی ناشی از آمار است. autovacuum ممکن است مقداری آمار ساخته باشد. بهبود احتمالی در کپی را نباید به رفع مشکل تولید تعبیر کرد.

بعد از این مرحله همان آزمون مرجع/فعال‌سازی/برابری/UPDATE rollback/غیرفعال‌سازی اجرا می‌شود. سقف کوئری‌های مرجع افزایش نیافته است. اگر باز هم اولین خواندن timeout شود، به جای تکرار یا افزایش سقف، باید برنامهٔ اجرای SQL و شرایط منابع روی کپی بررسی شوند. گزارش جدید phase و SQLSTATE پنج‌کاراکتریِ پالایش‌شده را ثبت می‌کند؛ پیام خام درایور یا اطلاعات اتصال منتشر نمی‌شود.

در موفقیت کلاستر خاموش و derived state غیرفعال است. در شکست، گزارش تعیین می‌کند چه چیزی commit شده؛ کلاستر خاموش می‌شود ولی غیرفعال‌سازی خودکار یا retry تراکنش commit نامعلوم انجام نمی‌شود. اعتبارسنجیِ گزارش قبلی جای کنترل زندهٔ هویت را نمی‌گیرد.

## محدودیت‌ها

- آزمایش کامل API یا همهٔ انواع trigger نیست.
- فرمول، cadence، timeout تولید و تاریخچهٔ اصلی تغییر نکرده‌اند.
- credentialهای آزمایش در طرح قبلی به شکل فایل محلی نگه‌داری می‌شوند؛ هشدار امنیتی PR23 با این اصلاح برطرف نشده است. آن فایل‌ها را منتشر نکنید یا وارد Git نکنید.
- نتیجهٔ اجرای ویندوزِ تلاش پس از ANALYZE هنوز دریافت نشده است.
