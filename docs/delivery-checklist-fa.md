# برنامهٔ پایان کار و تحویل با نظارت مالک

## مسئولیت‌ها و مرز اختیار

عامل مسئول اولویت‌بندی، کدنویسی، تست، گزارش شواهد و پیشنهاد قدم بعدی است. تأیید صریح مالک برای merge، استقرار/rollback سرور، ایجاد یا restore کپی دیتابیس، migration، تغییر تنظیمات عملیاتی و هر حذف/بازنویسی سابقه لازم است. مجوز یک merge به PR بعدی تعمیم ندارد. گذر از یک مرحله فقط با شاهد ثبت‌شده است، نه صرفاً سبزشدن CI.

## وضعیت ثبت‌شده در این شاخه

- PR16 در پایهٔ `3d13948` ادغام شده؛ این به معنی تأیید استقرار یا رفع ریسک عملکرد نیست.
- PR17 باز است و در آخرین بررسی GitHub، draft نبود. تمام ۱۴ check گزارش‌شده برای commit `1649638` موفق بودند (دو اجرای push/PR هم در این تعداد هست). وضعیت CI برای commit جدید باید دوباره بررسی شود.
- تست هدفمند همان commit: ۲۰ اجرا، ۱۹ پاس، ۱ skip اختیاری PG.
- دادهٔ مصنوعی PostgreSQL: روی ۲ میلیون رکورد / ۴۸ slot، endpointهای query قدیم و جدید یکسان بود. query کلی همچنان حدود ۷–۸ ثانیه بود؛ این ریسک رفع‌شده تلقی نمی‌شود.
- baseline کاملِ مرحلهٔ قبلی ۸ failure و ۲ error قدیمی داشت؛ سبزشدن GitHub به‌تنهایی اختلاف با اجرای محلی را توضیح نمی‌دهد. در این follow-up full suite دوباره اجرا نشده است.
- هیچ شاهدی در این مرحله برای ایجاد کپی دیتابیس، استقرار PR17 یا صحت ETA در چرخهٔ واقعی کارتریج ثبت نشده است.

## بودجهٔ عملکرد پیشنهادی، نه SLA تأییدشده

پیش از آزمون واقعی باید معیار قابل قبول ثبت شود تا بعداً بر اساس نتیجه عوض نشود. پیشنهاد اولیه: query کلی تکرارشده حداکثر ۲ ثانیه در پنج اجرای اندازه‌گیری‌شده و بدون تأخیر نامجاز در چرخهٔ جمع‌آوری. اولین اجرای مشاهده‌شده جدا گزارش می‌شود؛ صرف اتصال مجدد، آزمایش «cold cache واقعی» نیست. این بودجه هنوز نیازمند پذیرش مالک و تناسب با سخت‌افزار/بار واقعی است. موفقیت روی fixture مصنوعی جای آن را نمی‌گیرد.

## قدم فوری

فقط preflight کم‌هزینه و read-only از metadata سرور: نسخهٔ PostgreSQL، اندازهٔ DB، حجم تخمینی جدول snapshot، مجوز ساخت دیتابیس آزمایشی، وجود pg_dump/pg_restore و فضای دیسک. DSN/رمز/فایل env چاپ نشود. در این مرحله dump، restore، CREATE DATABASE، تست سنگین یا restart اجرا نمی‌شود.

پس از دریافت نتیجه، روش ساخت کپی و محل ذخیره با ظرفیت کافی انتخاب می‌شود و دستور کامل آن **برای تأیید مالک** ارائه خواهد شد. نام آزمایشی یا read-only بودن اتصال به‌تنهایی اثبات جدا بودن داده از دیتابیس اصلی نیست؛ منشأ و مقصد باید کنترل شوند. اجرای full suite با `.env` عملیاتی ممنوع است.

## خارج از ادعای تحویل فعلی

تأیید تمام SKUها، بازسازی خودکار سابقهٔ آسیب‌دیده، تضمین دقت برای کارتریج شارژشده بدون دادهٔ واقعی و حل تمام مسائل scanner با PR17 وعده داده نمی‌شوند. این موارد باید جداگانه پذیرفته یا خارج از دامنه ثبت شوند؛ مراحل پایان کار قرار نیست نامحدود و بدون معیار باشند.
