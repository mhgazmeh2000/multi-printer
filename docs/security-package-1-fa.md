# گزارش بستهٔ اول اصلاحات: امنیت گزارش‌گیری و نمایش

## دامنه و وضعیت

این بسته پس از ممیزی commit پایهٔ `f854938` روی شاخهٔ `arena/251a5796-multi-printer` پیاده شد. تغییری روی سرور، داده‌های عملیاتی، schema یا migration انجام نشده است. این گزارش به معنی حل تمام موارد ممیزی یا تأیید آماده‌بودن کامل سامانه برای تولید نیست.

## تغییرات انجام‌شده

### ۱. مرز اجرای SQL

- بررسی متنی/regex با تحلیل AST توسط `sqlglot` جایگزین شد: تنها یک SELECT یا ترکیب SELECTها پذیرفته می‌شود؛ CTE و زیرکوئری نیز بررسی می‌شوند.
- دسترسی جدول از ارجاع واقعی استخراج می‌شود، نه کلمه‌های موجود در comment یا literal. جدول `users` از فهرست گزارش‌گیری داخلی حذف شد؛ schemaهای غیرمجاز، table function، DML/DDL، INTO، lock، تابع ناشناخته و cast به نوع سفارشی رد می‌شوند.
- خروجی SQL آزاد با LIMIT بیرونی ۵۰۰ محدود می‌شود. حالت visual نیز حد مثبت و حداکثر ۵۰۰ دارد و دریافت نتیجه از cursor با `fetchmany(500)` انجام می‌شود.
- اجرای PostgreSQL در تراکنش read-only با statement timeout پنج ثانیه و lock timeout یک ثانیه انجام می‌شود. اجرای SQLite با query_only و progress handler محدود می‌شود.
- درایور PostgreSQL خارجی نیز همین سیاست دستور/تابع، timeout و سقف خروجی را دارد؛ جدول‌های آن محدود به فهرست جدول‌های داخلی نیستند.
- ساخت connection string با `make_conninfo` انجام می‌شود تا مقدار password/host نتواند پارامتر جدید DSN تزریق کند.
- گزارش آمادهٔ toner_levels_latest با ستون‌های موجود printer_counters و پارامترهای سطح تونر اصلاح شد.

### ۲. کنترل دسترسی

- preview و validate گزارش در تمام حالت‌های SQL، visual و prebuilt فقط برای admin مجاز است.
- ایجاد، ویرایش، تست اتصال و اجرای datasource فقط برای admin مجاز است. manager دیگر از allowlist سراسری مجوز نوشتن این مسیرها نمی‌گیرد.
- نمایش فهرست و تنظیمات mask‌شده برای manager حفظ شده است؛ دکمه‌های ایجاد/تست/حذف datasource برای او نمایش داده نمی‌شود.
- CSRF حذف یا ضعیف نشده و تست عدم پذیرش درخواست admin بدون token وجود دارد.

**تغییر سازگاری عمدی:** داشبورد یا ابزار سفارشی manager که به preview یا datasource query متکی بوده، اکنون 403 می‌گیرد. این بسته جایگزین مبتنی بر گزارش‌های محدود به دفتر/سازمان فراهم نمی‌کند. بازگرداندن دسترسی گسترده راه‌حل مناسبی نیست؛ آن مسیر باید در طراحی مجوز داده جداگانه ساخته شود.

### ۳. تنظیمات و اسرار datasource

- mask و ادغام تنظیمات به‌صورت recursive برای dict/list انجام می‌شود؛ placeholder رمز قبلی را نگه می‌دارد و کلیدهای ارسال‌نشده حذف نمی‌شوند.
- تنظیمات با schema فعلی هر driver بررسی می‌شوند: فیلد الزامی، نوع، enum، طول، port و timeout. فیلد ناشناخته و ساختار تودرتوی ناسازگار با schemaهای تخت فعلی رد می‌شود.
- خطاهای اعتبارسنجی با 400 برمی‌گردند و خطای عمومی اتصال/اجرا متن خطای درایور را مستقیماً به کاربر نمایش نمی‌دهد.

**محدودیت:** masking رمزنگاری در حالت ذخیره‌شده نیست. اعتبارنامه‌های datasource همچنان در پایگاه‌داده متن ساده هستند. بعضی مسیرهای قدیمی metadata/logging نیز بازطراحی سراسری نشده‌اند.

### ۴. نمایش HTML و handlerها

- escapeHtml برای quoteها، null و مقادیر غیررشته‌ای اصلاح شد؛ jsArg برای جای‌گذاری امن رشته در handlerهای inline باقی‌مانده اضافه شد.
- حذف پرینتر و افزودن سریع دستگاه کشف‌شده به event delegation منتقل شد؛ نام دستگاه دیگر کد اجرایی دکمه نیست.
- مسیرهای متعدد نمایش نام، مدل، سریال، firmware، cartridge، alert، گروه، preview افزودن گروهی و تاریخ تحلیل import escape شدند.
- کارت datasource نام/type/UID و خطای نمایشی را escape می‌کند؛ handler تست/حذف با addEventListener متصل می‌شود.
- نسخهٔ cache دارایی dashboard تغییر کرد.

**محدودیت:** این کار بازنویسی تمام innerHTMLها یا حذف تمام handlerهای inline و unsafe-inline از CSP نیست؛ ادعای مصونیت کامل رابط در برابر XSS نمی‌شود.

## راهنمای استقرار و برگشت

1. این بسته schema migration ندارد. فرایند عادی بکاپ و انتشار پروژه را حفظ کنید.
2. پس از دریافت نسخهٔ منتشرشده، وابستگی‌ها را در محیط همان سرویس نصب کنید: `python -m pip install -r requirements.txt`. وابستگی جدید `sqlglot>=26,<31` است. سپس سرویس را از روش معمول استقرار restart کنید.
3. برای PostgreSQL یک role جداگانهٔ غیرsuperuser، بدون اختیار نوشتن/ساخت object و با SELECT فقط روی جدول‌ها یا viewهای گزارش‌گیری موردنیاز فراهم کنید. schema/search_path و مجوز اجرای functionها باید تحت کنترل DBA باشد. از حساب اصلی برنامه یا حساب مالک schema برای گزارش‌گیری استفاده نکنید.
4. اتصال گزارش‌گیری داخلی را با متغیر محیطی اختیاری `REPORTING_PG_DSN` تنظیم کنید؛ مقدار واقعی را در secret store/محیط سرویس بگذارید، نه مخزن یا گفتگو. در نبود این متغیر، کد برای سازگاری از اتصال فعلی برنامه استفاده می‌کند؛ بنابراین جداسازی نقش هنوز اجباری نشده است. datasource خارجی نیز باید اعتبارنامهٔ محدود خودش را داشته باشد.
5. روی staging PostgreSQL تأیید کنید: admin فقط جدول‌های مجاز را می‌خواند، manager پاسخ 403 می‌گیرد، نوشتن در اتصال گزارش‌گیری ممکن نیست، timeout فعال است، credential در پاسخ API آشکار نمی‌شود و نام حاوی quote/HTML متن عادی باقی می‌ماند. خروجی بیش از ۵۰۰ ردیف برنگردد.
6. اگر `ASSET_VERSION` در محیط override شده است، هنگام انتشار آن را نیز تغییر دهید تا JS قبلی از cache استفاده نشود.
7. برگشت از طریق بازگرداندن artifact قبلی و restart معمول سرویس است؛ چون schema تغییر نکرده downgrade دیتابیس لازم نیست. برگشت کد حفاظت‌های این بسته را نیز برمی‌گرداند، پس در صورت ضرورت، دسترسی مسیرهای گزارش‌گیری را تا انتشار اصلاحیه محدود کنید. از reset/migration دیتابیس برای rollback این بسته استفاده نکنید.

این راهنما فرمان تغییر سرور اجرا نکرده است. ساخت role و آزمایش staging نیازمند تصمیم استقرار و بررسی مجوزهای واقعی محیط شماست.

## کارهای خارج از این بسته

- اصلاح normalization شناسهٔ کارتریج در enhanced collector و تشخیص vendor/OID.
- اصلاح batch/negative-cache و جلوگیری از تداخل cycleهای poll، شامل side effectهای دیتابیس.
- اصلاح مدل اعتماد، نمونه‌های sparse، status/unit/precision و invalid observation در v2.
- اصلاح وابستگی cache به catalog و هزینهٔ query روی تاریخچهٔ بزرگ.
- اصلاح fixtureها و تست‌های قدیمی مستقل از این بسته.
- طراحی گزارش manager با محدودیت ردیفی/دفتر، رمزنگاری اعتبارنامه‌ها و بازطراحی کامل CSP.
