# بستهٔ دوم امنیت: پنل متنی، جزئیات هشدار و encoding تست‌ها

## دامنه

این بسته فقط مسیرهای نمایش پنل و تست‌های مرتبط را تغییر می‌دهد. Collector، محاسبات v2، polling، دادهٔ عملیاتی، schema، مجوزهای API و تنظیمات PostgreSQL تغییر نکرده‌اند. این بسته روی سرور اجرا نشده است.

## رفتار پنل متنی

- `plain`: محتوا با `textContent` نمایش داده می‌شود؛ HTML تفسیر نمی‌شود و سطرهای جدید حفظ می‌شوند.
- `markdown`: متن توسط Marked پردازش می‌شود و سپس خروجی آن از DOMPurify می‌گذرد؛ HTML درون Markdown نیز از همین سیاست عبور می‌کند.
- `html`: فقط HTML پالایش‌شده نمایش داده می‌شود، نه HTML آزاد.
- نبود `mode` معادل `markdown` است، مطابق پیش‌فرض schema فعلی. mode ناشناخته فقط متن نمایش می‌دهد.
- اگر کتابخانهٔ لازم در دسترس نباشد، مرورگر توسط DOMPurify پشتیبانی نشود یا parser/sanitizer خطا بدهد، محتوا به‌صورت متن عادی نمایش داده می‌شود؛ fallback به HTML خام نداریم.
- محتوای صریحاً خالی دیگر با دادهٔ query جایگزین نمی‌شود؛ در نبود content، دادهٔ رشته‌ای query قابل استفاده است و از همان سیاست نمایش عبور می‌کند.

### قالب‌بندی مجاز و تغییر سازگاری

پاراگراف، سطر جدید، heading، bold/italic، خط‌خورده، فهرست، نقل‌قول، code/pre، جدول و لینک با سیاست URI امن DOMPurify پشتیبانی می‌شوند. attributeها فقط `href` و `title` هستند. script، event handler، style، تصویر/رسانه، iframe، فرم، SVG/MathML، ID/name و data attribute مجاز نیستند.

**تغییر عمدی:** پنل‌های قدیمی متکی بر تصویر، CSS سفارشی، فرم، iframe یا JavaScript دیگر آن قابلیت‌ها را نخواهند داشت. لینک‌های عادی خارجی همچنان ممکن‌اند؛ این بسته سیاست اعتماد به مقصد لینک یا جلوگیری از phishing نیست.

محتوای ذخیره‌شده در دیتابیس بازنویسی نمی‌شود. مرز پالایش هنگام رندر است؛ هر مصرف‌کنندهٔ آیندهٔ این محتوا نیز باید آن را غیرقابل اعتماد بداند و پالایش مناسب خودش را انجام دهد. sanitization سمت سرور یا migration داده جزو این بسته نیست.

## جزئیات هشدار

تمام فیلدهای پویا شامل عنوان، نام/IP دستگاه، کد، زمان، پیام و اقدام پیشنهادی قبل از جای‌گذاری در قالب مودال escape می‌شوند. severity فقط به رنگ/برچسب ثابت نگاشت می‌شود. دو دکمهٔ بستن از `addEventListener` استفاده می‌کنند. کلیک روی هشدار، استفادهٔ مجدد از مودال و فیلترهای severity حفظ شده‌اند.

مسیر خطای نوع پنل ناشناخته هم به نمایش متن تبدیل شد؛ کلیدهای prototype به‌عنوان renderer انتخاب نمی‌شوند.

## کتابخانه‌های محلی و تست DOM

- DOMPurify: `3.4.17`
- Marked: `18.1.3`
- jsdom برای تست: `31.0.0`

فایل‌های مرورگر و مجوزهایشان در `web/static/vendor/dompurify/` و `web/static/vendor/marked/` ثبت شده‌اند و قبل از renderer بارگذاری می‌شوند. مرورگر برای این قابلیت به CDN نیاز ندارد. نسخه‌های دقیق و integrity وابستگی‌های ابزار تست در `package-lock.json` ثبت شده‌اند.

**برای اجرای معمول برنامه روی سرور به Node، npm install یا build جدید نیاز نیست.** فایل‌های مرورگر از قبل داخل مخزن هستند. Node فقط برای تست DOM و بازتولید vendor assetها لازم است.

روی یک checkout آزمایشی جداگانه با Node پشتیبانی‌شده (Node 22.22.2 به بعد در شاخهٔ 22، یا نسخهٔ پشتیبانی‌شدهٔ jsdom از شاخه‌های جدیدتر):

```text
npm ci
npm test
```

این ۱۲ تست Node مستقل از تست‌های Python هستند؛ اجرای unittest به‌تنهایی آن‌ها را اجرا نمی‌کند. CI با Node 22، نصب lockfile و `npm test` به‌صورت مرحلهٔ الزامی به‌روز شده است. یک job مستقل Windows/Python 3.14 نیز برای ۱۶ تست امنیتی و تست‌های DOM اضافه شده؛ نتیجهٔ آن پس از اجرای GitHub Actions مشخص می‌شود. برای بازتولید فایل‌های vendor پس از نصب نسخه‌های lockشده:

```text
npm run vendor:panels
```

نسخه‌های sanitizer و parser باید در آینده همراه تست payloadها و فایل‌های vendor به‌روز شوند. تست برابری فایل‌های ثبت‌شده با بسته‌های نصب‌شده نیز وجود دارد.

## اصلاح encoding تست‌های Python

در سه فراخوانی Node در `tests/test_security_hardening.py`، `encoding="utf-8"` صریح شد. این تغییر برای رفت‌وبرگشت متن فارسی است و به `PYTHONIOENCODING` به‌تنهایی متکی نیست. با این حال اجرای کل suite قدیمی روی ویندوز هنوز ممکن است برای بخش‌های دیگر به حالت UTF-8 نیاز داشته باشد؛ ادعای اصلاح encoding تمام تست‌ها نداریم.

## نتیجهٔ آزمون در محیط توسعه

- ۱۲ تست DOM با jsdom و فایل‌های واقعی vendor/renderer: همه پاس، بدون skip. پوشش: payloadهای HTML/SVG/MathML، URI ناامن، فیلدهای هشدار، close/reopen، قالب‌بندی سالم، modeها و fallback در نبود/خرابی کتابخانه.
- همان ۱۲ تست با renderer نسخهٔ پایه: ۱۰ شکست و ۲ موفق؛ نشان می‌دهد تست‌های جدید نسبت به رفتار آسیب‌پذیر حساس‌اند.
- ۷۶ تست Python مرتبط با امنیت، query، datasource، overview، startup، paper size، panel base و dashboard builder: همه پاس.
- دو تست ارتباط متنی با Node تحت locale غیر UTF-8 (`LC_ALL=C` و `PYTHONUTF8=0`): پاس. این آزمایش لینوکسی جایگزین تأیید روی ویندوز نیست.
- unittest کامل: ۹۶۰ تست، ۸ failure، ۲ error و ۷۵ skip؛ همان نام خطاهای شناخته‌شدهٔ قبلی در backup tools، cutover و انتظارهای migration/schema. این بسته آن مشکلات را حل یا مخفی نمی‌کند؛ اجرای کامل سبز نیست.
- parity مسیرهای Python: ۹۶۰ مورد، بدون حذف/تکرار.
- هر ۱۰ golden scenario: بدون اختلاف.
- `npm ci`، syntax check فایل renderer و `git diff --check`: موفق.

آزمون امنیتی در DOM شبیه‌سازی‌شده انجام شده و نبود عناصر/attributeهای اجرایی را بررسی می‌کند؛ تست تعاملی در Chrome/Edge ویندوز یا آزمون نفوذ کامل مرورگر انجام نشده است. سیاست کلی CSP و تمام innerHTMLهای پروژه بازطراحی نشده‌اند.

## انتشار

پس از review و merge، انتشار معمول کد، restart سرویس و refresh سخت مرورگر کافی است. migration و تغییر دیتابیس لازم نیست. نسخهٔ پیش‌فرض `ASSET_VERSION` تغییر کرده است؛ اگر در محیط override شده باید هنگام انتشار آن را نیز تغییر دهید. روی staging حالت‌های متن، قالب‌بندی Markdown/HTML و باز/بسته‌شدن هشدار را بررسی کنید. اجرای تست‌ها را همچنان در کپی جدا از برنامه و دیتابیس عملیاتی انجام دهید.
